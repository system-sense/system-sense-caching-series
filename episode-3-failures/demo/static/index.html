Penetration, Avalanche and Breakdown are three different bugs with three different fixes. Every number below is one the application counted while the attack was running.

The buttons here fire a few thousand requests, so they finish while you watch. The full-sized attacks are the k6 scripts: docker compose run --rm load-test run /scripts/penetration.js

Failure 1 · Cache Penetration

Requests for ids that were never issued. Redis has never heard of them and Postgres has nothing to return, so there is nothing to cache — and every request goes all the way to disk.

Run null_cache against both attacks. It absorbs the repeated ids almost completely and barely touches the random ones — every new id costs its own query before there is a tombstone to find. That is what the Bloom filter is for.

Failure 2 · Cache Avalanche

A batch job warms every key at once, with one TTL. Ordinary traffic, nothing hostile — but every key reaches the end of the same TTL in the same instant.

Failure 3 · Cache Breakdown

One hot key, many readers, and it expires underneath them. Not many keys — one. Nothing in Cache-Aside says "somebody else is already fetching this", so every reader in flight fetches it too.

Defense
Not run yet.

This episode does not fix it. A TTL cannot: the key is gone, and every reader is right to go and get it. The fix is a lock that lets one reader through and makes the rest wait — Episode 4.
